# Working conventions for the ℚ(√241) port

Shared by every agent working on the port. The plan is
[../SQRT241_PORT.md](../SQRT241_PORT.md); the mathematics is
`papers/0.04273/research/construction.md`; finite data
and reference scripts are in `papers/0.04273/certificates/`.

## Target

`ChallengeZeta241.lean` states the theorem: exponent `10427/10000`,
one hypothesis H on the canonical genus field `E` (degree 512) in the
fixed-base form with ε = 1/300, `logRD = (9/4) log 2 + (1/2) log 3615` and
ceiling `852/10000`. `SolutionZeta241.lean` restates it and applies
`UnitDistance.Sqrt241.target_of_canonical_genus_zeta_bound` (`Final.lean`); the
submission account is [SUBMISSION.md](SUBMISSION.md).

## Architecture (interfaces between streams)

1. **Downstream (stream A).** `UnitDistance.Sqrt241.target_of_growing_galois_fields`:
   the analogue of
   `SIntegerCRT.target_of_growing_retained_galois_fields_sharperFixedBase_run20260920`
   (`UnitDistance/SharperPairFixedBaseBridgeRun20260920.lean`) for the witness
   `UnitDistance.Sqrt241.Witness` (five local types, `Fin 5`), a fixed base `M`,
   `65536 ≤` centralizer index, √3 and √−1 in `M`, ε = 1/300 and threshold
   `Sqrt241.Witness.ceiling`.
2. **Analytic bridge (stream B).** From H on `CanonicalGenus.Carrier` and the
   local types of `M` at 2, 29, 7 and the census primes, derive
   `fixedBaseResidueCeiling M Witness.logRD (1/300) < Witness.ceiling`.
3. **Tower (streams C, D, E).** Construct `M` (the D₃-retained field of the
   cut group over B) and the growing fields `K_j` (Galois over ℚ) with all
   hypotheses of 1 and 2. Everything lives in `AlgebraicClosure ℚ`; B is
   `ℚ⟮CanonicalGenus.baseRoot⟯`.

## Rules

* Work in `lean-formalization/`. Toolchain: `./.toolchain/bin/lake`,
  `./.toolchain/bin/lean`. Build a module with
  `./.toolchain/bin/lake build UnitDistance.Sqrt241.X.Y`; check a single file
  with `./.toolchain/bin/lake env ./.toolchain/bin/lean File.lean`. Existing
  modules are compiled; never run `lake update`, `lake clean` or a bare
  `lake build`.
* Only create or change files under `UnitDistance/Sqrt241/`, `scripts/sqrt241/`,
  `certificates/*241*` and `docs/sqrt241/`. The ℚ development is a verified
  Palomar package and stays byte-identical; copy what you need to change.
* Module header as in the existing files (`module`, `public import …`,
  `@[expose] public section`, `set_option backward.privateInPublic true`);
  namespace `UnitDistance.Sqrt241.…`.
* Generated modules start with `-- Generated by scripts/sqrt241/<script> — do
  not edit by hand.` (generated blocks inside a module are enclosed by
  `-- BEGIN Generated by …`/`-- END Generated by …`). Change the generator and
  regenerate instead of editing them; see [SUBMISSION.md](SUBMISSION.md).
* Raise `maxHeartbeats`/`maxRecDepth` only for the declarations that need it
  (`set_option … in`), not for a whole file.
* No `sorry`, `admit`, `axiom`, `native_decide`, `implemented_by`/`extern`.
  `decide +kernel` is fine. Deliverables may depend only on `propext`,
  `Classical.choice`, `Quot.sound` (check `#print axioms` from a scratch file
  outside the repository).
* Several agents share the worktree and the machine (8 cores, 31 GB): run at
  most ONE Lean process at a time (lake build or lake env lean), `timeout` on
  long commands, build only your own modules. Before starting a Lean process
  check `free -g`: if less than 6 GB is available, wait (do non-Lean work or
  poll with a short loop) instead of starting it. No git commits, stashes or
  resets.
* Tower work follows [TOWER_PLAN.md](TOWER_PLAN.md) (architecture §1, work
  packages T0–T12 in §3). Directory ownership for the tower: `ProP/` and
  `Tower/OmegaB.lean`, `Relation/` (T0, T4); `Tower/Bridge*.lean`,
  `Tower/ConjugationTransport.lean`, `Generators/`, `Presentation/` (T1, T3,
  T6); `Local/` (T5); `GroupData/`, `Cut/` (T7, T8); `Retained/`, `Levels/`
  (T9, T10); `Discriminant/` (stream E, done); `DyadicLink/` (T11); `Genus/`, `Analytic/`
  (stream B); `Base/` (stream C1). Import other streams' modules; never edit
  them — ask the coordinator (in your final report) for changes you need.
* Each stream keeps a note `docs/sqrt241/<STREAM>.md`: exact declarations and
  statements delivered, open items, rebuild commands.
